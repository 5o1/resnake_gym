# 不规则观测与动作块控制设计

## 1. 当前基线不覆盖什么

`ReSnake-v0` 是同步、完全可观测的历史环境，只保留复现用途。当前训练入口使用
`ReSnakePerturbed-v1` 和 `AsyncGamepad`：策略收到可能延迟或重复的场景快照，输出
未来 `L` 帧的完整20维手柄状态，环境在两次决策之间继续推进。默认游戏频率为
10 tick/s，决策间隔随机为2—5 tick，动作块长度为8。

`AsyncGamepad`已在逻辑tick域模拟跳帧、旧画面、命令延迟、丢帧和队列耗尽；这使它
比同步环境更接近部署时序，但仍没有覆盖以下现象：

- 延迟范围是工程配置，不是从实际推理、IPC、网络或机械平台测得的分布；
- 事件仿真不会因推理变慢而按墙钟独立推进，也没有操作系统调度抖动；
- 真实HID采样、机器人执行误差和接触过程没有接入；
- 跨主机时钟校准、网络乱序和长尾阻塞没有进入训练。

因此，事件仿真的成功率和批量吞吐不能直接作为实时闭环证据。

## 2. 部署时序

游戏以固定逻辑频率 `f_game` 运行。第 `i` 次可用观测到达控制端时，控制端记录：

- 观测对应的游戏 tick `t_obs`；
- 当前控制 tick `t_now`；
- 观测年龄 `d_obs = t_now - t_obs`；
- 从上一次有效观测到现在经过的 tick 数；
- 此期间实际执行的动作，而不只记录计划动作。

策略的输入应包含最近一次状态、上述时间信息和已执行动作历史。每次策略调用的
控制周期起点记作动作块的 `origin`，输出长度为 `L` 的动作块：

```text
[a(origin), a(origin+1), ..., a(origin+L-1)]
```

动作块必须携带 `origin`，第 `j` 项只允许用于目标 tick `origin+j`。如果数据包在
`arrival` tick 才到达，执行器丢弃所有满足 `origin+j < arrival` 的过期前缀，从
`j = arrival-origin` 开始安装仍未错过的动作；不能把 `chunk[0]` 顺延到
`arrival`，否则同一个输出位置在不同延迟下会具有不同时间语义。

执行器按目标 tick 保存计划。较新的 sequence 只覆盖重叠 tick 上的旧计划；较旧
的数据包即使更晚到达，也不能覆盖已经由新 sequence 安装的同一目标 tick。执行
日志同时保存 `origin`、完整目标范围、过期前缀长度、每个实际动作的目标 tick、
chunk 下标和来源 sequence。这样才能区分模型输出错误、数据包迟到和队列耗尽。

动作块长度按部署链路的延迟分布确定：

```text
L >= ceil(p99(观测间隔 + 推理延迟 + 传输延迟) * f_game) + 余量
```

若某个目标tick没有可执行报告，当前执行器发送20维全零的中立手柄报告。中立报告
不会命令蛇停下；蛇继续保持既有方向是游戏自身规则的结果。该降级语义不读取棋盘，
也不替模型选择“安全动作”。

## 3. 训练环境

保留同步环境作为确定性逻辑内核，另加时序包装层。当前版本直接使用可变控制间隔
`K_i`：每隔2—5个底层tick调用一次策略，但策略拿到的是采集线程最近送达的状态，
因此可能重复旧状态，也可能跳过数量不定的中间状态。包装层负责：

1. 每个底层 tick 都推进游戏；
2. 按时序配置决定哪些底层状态被采集线程送达；
3. 从状态历史中返回带延迟的观测；
4. 维护按绝对目标 tick 索引的动作计划；
5. 推进本次实际的 `K_i` 个tick，并累积期间的逐tick奖励；
6. 在 `info` 中返回实际观测年龄、推进 tick 数、执行的动作和队列是否耗尽。

第一轮使用合成范围扫描，例如不同的观测间隔、延迟和丢帧率。真机链路打通后，
用采集线程、推理进程、网络和 HID/机器人驱动的时间戳形成经验分布。正式训练从
经验分布采样，正式测试使用独立采集的整段时序轨迹，不能把同一条轨迹切成帧后
随机分到训练集和测试集。

每次策略调用按实际持续时间换算折扣：

```text
gamma_decision_i = gamma_tick ** K_i
reward_decision_i = sum(gamma_tick ** j * reward_tick[j], j=0..K_i-1)
```

包装层在 `info` 中同时保留逐 tick 奖励、未折扣总和和上述折扣总和，返回给 PPO 的
是折扣总和。这样一次策略调用内的第 `j` 个奖励仍处在正确的逻辑时间上，下一次
策略调用的bootstrap使用`gamma_tick ** K_i`。因此每条样本都记录实际持续时间，
而不是把长短不同的间隔都当成同一个普通PPO step。

## 4. 模型输入与输出

当前先维护一个小型时序基线，再考虑更大的视觉—语言—动作模型。

输入：

- 最近送达的 `scene-grid-v2` 场景，形状为 `14×S×S`，并含有效棋盘mask；
- 画面年龄、距上次决策时间和是否收到新画面的基础时间量；
- `policy-time-v2` 的五维时间上下文和每个动作槽的目标时间；
- 上一个完整 `[L,20]` 计划动作块及其年龄；
- 从上次决策以来实际执行的完整20维报告历史、报告年龄和有效掩码。

输出：

- 所有阶段统一输出 `torch.Tensor[B,L,20]`；20维严格采用
  `xinput-normalized-v1` 的按钮、摇杆和扳机顺序；
- 环境只接受完整 `[L,20]` 手柄报告，不接受整数方向或三分类相对转向；
- 可微下游保留原张量及梯度，只有执行边界才转换为NumPy或wire格式。

当前默认基线用蛇头局部卷积、全局注意力和GRU编码上述观测，再输出14个Bernoulli按钮分布和6个
轴潜变量分布。完整20维仍被采样、执行和交给下游；Snake只读取十字键0—3与左摇杆
14—15，所以PPO/SIL只计算这六个独立因子的边缘log probability和entropy。策略在
report、history及previous_chunk进入循环记忆前也遮蔽其余控件，避免无效控件通过
反馈改变未来有效动作。这个遮罩是Snake训练器内部的因果假设，不是动作API降成六维。
如果游戏绑定或跨控件相关结构改变，必须重新审计该假设。

默认parallel头一次产生整个chunk，各时间槽在给定循环状态下独立采样；可选GRU
decoder共享逐槽状态，但当前随机分布仍未实现真正自回归条件化。这两者都只是待比较
基线，不能由结构直接推断优劣。

## 5. 纯在线强化学习中的分布问题

主线不使用人工演示、行为克隆或教师标签。PPO 每轮用当前策略在环境中采样，
所以策略犯错后到达的状态也会进入后续训练。这里需要处理的不是“人类轨迹到
模型轨迹”的偏移，而是训练环境与测试环境的时序分布不同：

- 训练中的观测年龄和命令延迟是否覆盖测试范围；
- 真实链路的连续丢帧和长尾卡顿是否在训练中出现；
- 训练与测试是否使用同样的动作块、队列和过期丢弃规则；
- 棋盘尺寸、逻辑帧率和初始 seed 是否超出训练覆盖。

当前训练CLI以取食事件决定可变rollout：每环境至少128、至多512次决策，达到最低
长度后全局累计4次取食才提前更新；死亡和截断不满足配额。PPO仍训练整批失败与
未完成样本。未终止回合取食时，SIL会立即保留带next-value bootstrap的最新前缀，
每环境至多一份；它不把该边界改成PPO的done。PPO的循环梯度另用64步burn-in和最长
128步learn窗口。完整定义和消融要求见[成功事件训练设计](ppo-success-training-design.md)。

当前训练逐决策从合成范围采样间隔与延迟，还没有按episode重放实测trace。完整链路
可用后，计划在每个episode采一条时序trace，整段重放观测到达、命令延迟和丢帧事件；
训练主要从实测trace采样，另加少量更长延迟和连续丢帧作压力条件。训练、验证和测试
应按完整trace与游戏seed划分，不拆分同一条轨迹。

形式化评测只使用冻结的单模型输出。队列耗尽时执行事先定义的中立手柄报告；评测中
不根据棋盘选择安全动作，也不接入人工、规则规划器或教师策略。

## 6. 评测矩阵

每个模型至少分开报告以下条件：

| 变量 | 条件 |
| --- | --- |
| 棋盘 | 31×20目标场景；小棋盘只作单元测试；其他尺寸仅作单独泛化评估 |
| 观测间隔 | 固定；训练范围内随机；训练范围外长尾 |
| 观测年龄 | 0；经验分布；比训练更慢的压力条件 |
| 动作块 | 单步；固定 `L`；队列偶发耗尽 |
| 策略 | 同步单步 PPO；异步动作块 PPO；时序模型消融 |
| 执行方式 | 离线批量；batch=1 无节拍；batch=1 实时节拍 |

闭环通关率是任务指标。另报告单环境推理和控制循环的 50%、95%、99% 延迟上界、
最大值和 deadline miss rate。游戏侧实时测试不包含 HID、网络和机械臂延迟；完整
系统接入后需要重新测量整条链路。

## 7. 设计依据

- Zhao 等人的 ACT 使用动作块表示未来一段控制序列；本项目只借用这个时序接口，
  训练仍是从零在线 PPO：<https://arxiv.org/abs/2304.13705>。
- Yuan 和 Mahmood 的真实机器人实验把环境持续运行时的动作周期与学习计算分开，
  说明同步模拟的 step 吞吐不能替代实时动作周期测量：
  <https://arxiv.org/abs/2203.12759>。
- Kapturowski 等人的R2D2比较了存储循环状态与burn-in；本项目只借用状态重建思路，
  仍使用on-policy PPO及独立的SIL回放：<https://openreview.net/forum?id=r1lyTjAqYX>。
- Spooner等人的FPG说明动作—目标影响结构可用于降低score-function方差，也说明错误
  指定结构会带来偏差；当前六因子边缘目标是项目自己的Snake因果适配，不是FPG实现：
  <https://proceedings.neurips.cc/paper_files/paper/2021/hash/2ba8698b79439589fdd2b0f7218d8b07-Abstract.html>。
